# Brightness Control

A Windows tray app for changing brightness on every screen without touching the monitor's buttons.

- **Every screen in one place.** External monitors are controlled over **DDC/CI**; the laptop screen through Windows (**WMI**).
- **All screens slider** and **Night / Evening / Day / Max** presets.
- **Monitor settings** per monitor: contrast, colour preset (sRGB, 6500 K, …) and input source. Only what each monitor reports supporting is shown.
- **Brightness matching.** Screens at the same % rarely look the same. Run **Calibrate matching…** once: match a grey square on each screen by eye, and from then on one slider looks equally bright everywhere.
- **Follow laptop brightness** (optional). External monitors follow the laptop's brightness keys and Windows adaptive brightness.
- **Doesn't lose monitors.** Screens that don't answer stay listed and are re-checked when you open the panel, after display changes and after sleep. A detection log explains what happened.
- Light/dark theme follows Windows, sharp on high-DPI screens, keyboard and screen-reader friendly.
- Collects no data and never goes online. See the [privacy policy](docs/privacy.md).

## Use

Click the sun icon in the taskbar to open the panel. Right-click it (or use **⋯** in the panel) for **Refresh screens**, **Match brightness across screens**, **Calibrate matching…**, **Follow laptop brightness**, **Start with Windows**, **Open detection log** and **Exit**.

Sliders respond to dragging, the mouse wheel and the keyboard (arrows, Page Up/Down, Home/End). The arrow next to a monitor's name opens its settings. Esc closes the panel.

## If a monitor doesn't respond

The monitor itself has to allow software control. In the monitor's on-screen menu:

1. Turn **DDC/CI** on (often under Setup / System).
2. Set **ECO Mode** to **Standard** and turn off **Dynamic Contrast**. These modes lock brightness.
3. Connect directly to the computer. Docks and USB display adapters usually block DDC/CI.

Then right-click the tray icon and choose **Open detection log** to see what the app found (`%LOCALAPPDATA%\BrightnessControl\detect.log`, or the package's `LocalState` folder for the Store version).

## Build

Needs the [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) (`winget install Microsoft.DotNet.SDK.10`).

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1        # bin\BrightnessControl.exe
```

### Microsoft Store package

Also needs the Windows SDK (`winget install Microsoft.WindowsSDK.10.0.26100`) for `makeappx` and `makepri`.

```powershell
# Local test build with a placeholder identity
powershell -ExecutionPolicy Bypass -File .\build-msix.ps1

# Store build: identity values from Partner Center > Product management > Product identity
powershell -ExecutionPolicy Bypass -File .\build-msix.ps1 -IdentityName "<Package/Identity/Name>" `
    -Publisher "<Package/Identity/Publisher>" -PublisherDisplayName "<Publisher display name>" `
    -DisplayName "<the app name you reserved>"
```

Output: `dist\BrightnessControl_<version>.msixbundle` (x64 + arm64, self-contained) to upload to Partner Center. The Store signs it. Listing text is in [docs/store-listing.md](docs/store-listing.md).

Icons are generated by `dotnet run --file tools/make-assets.cs`.

Tests (capabilities parser, matching curves): `dotnet run --file tests/unit.cs -- bin/BrightnessControl.dll`.

- [ ] Schedules and sunrise/sunset

```
  LaptopWatcher.cs            follow laptop brightness
  Panel.cs, FlatSlider.cs     the flyout UI
  App.cs, Program.cs          tray icon, menu, startup
packaging/                    MSIX manifest and icons
tools/make-assets.cs          icon generator
docs/                         privacy policy, Store listing, research
build.ps1 / build-msix.ps1    build scripts
```
